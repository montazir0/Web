VORTEX NETWORK CONTROL CENTER WEB
الخريطة الهندسية النهائية لموقع ويب حقيقي
جاهزة للإرسال إلى Build في Google AI Studio
قرار معماري حاسم
الموقع لا يدّعي إدارة Windows أو Wi-Fi أو الراوتر مباشرة من المتصفح. كل عملية محلية أو على شبكة خاصة تحتاج VNC Local Agent مثبتًا على جهاز المستخدم، أو تبقى Demo/Read-only/NOT_IMPLEMENTED. السحابة لا تحاول الاتصال بعناوين LAN الخاصة.

المرجع الأساس: VNC_Final_Engineering_Roadmap_AR.docx
الناتج المطلوب: Full-stack web application قابلة للمعاينة ثم النشر، مع React frontend وNode.js server runtime.
 
1. الملخص التنفيذي
تحول هذه الخريطة مشروع VNC من تطبيق سطح مكتب محلي إلى منصة ويب Full-stack، مع الإبقاء على مبدأ الصدق التقني. الواجهة السحابية تعرض الحساب والأجهزة والجلسات والتقارير، بينما تنفيذ عمليات Windows/Wi-Fi/LAN يتم حصراً من خلال Local Agent موثوق ومقترن بالحساب. عند غياب Agent لا تظهر نتائج وهمية ولا أزرار تنفيذ فعالة.
المبدأ الحاكم
Cloud UI لا تساوي Local Network Access. نجاح Ping سحابي لا يثبت حالة جهاز منزلي. لا تُعرض أي Telemetry إلا مع source وtimestamp وverified. الأوامر الحساسة تحتاج Capability + Consent + Agent online + signed job + post-verification.

3. التصميم المعماري النهائي
1.	React + TypeScript frontend داخل Google AI Studio Build.
2.	Node.js/TypeScript server routes لجميع الأسرار وقواعد الأعمال واستدعاءات Gemini.
3.	Firebase Authentication لتسجيل الدخول، وFirestore لتخزين الحسابات والأجهزة والوظائف والنتائج والسجل.
4.	Local Agent على Windows يتصل Outbound فقط بالخادم، يرسل heartbeat ويسحب Jobs الموقعة ويرجع Results موقعة.
5.	لا توجد اتصالات Inbound من السحابة إلى LAN، ولا تخزن السحابة كلمات مرور الراوتر/Wi-Fi.
6.	كل Telemetry تحمل source=agent|provider|user|demo وverified وcapturedAt وexpiresAt.
7.	Demo mode بياناته موسومة synthetic=true ولا يختلط بحسابات Production.
4. ما يستطيع الموقع فعله وما لا يستطيع

Agent Online	تنفيذ القدرات التي يعلنها Agent فقط، مع consent وjob state ونتيجة متحققة.

Wi-Fi credentials	تبقى محليًا في Agent/Windows؛ لا تُرفع للسحابة.

ONT values	null إذا لم يثبت Provider الموثق القيمة.
Repair	لا زر Execute دون preview للمخاطر والتأكيد وAgent capability وverification plan.

10. أمن الموقع
النطاق	القاعدة
Authentication	Firebase Auth؛ تحقق server-side من ID token.
Authorization	كل استعلام يقيّد ownerUid؛ لا ثقة بمعرفات العميل.
CSRF	SameSite cookies إن استُخدمت + CSRF token للعمليات المغيرة.
XSS	React escaping؛ لا dangerouslySetInnerHTML إلا Sanitizer موثق.
Secrets	GEMINI_API_KEY وأي سر server-side فقط في Secrets panel.
Agent trust	Public-key pairing، nonce، timestamp، signature، replay protection.
Data minimization	لا حفظ passwords/tokens/cookies/authorization في Firestore أو logs.
Validation	Schemas مشتركة مثل Zod؛ رفض unknown fields في العمليات الحساسة.
Rate limits	Login-sensitive، pairing، jobs، AI explain.
Headers	CSP، frame-ancestors، nosniff، referrer policy، permissions policy.
Audit	كل Job وConsent وRevoke يسجل، مع Redaction.
Deletion	Delete account يمسح البيانات أو يجدول حذفًا موثقًا.

11. Local Agent Contract
مهم
Google AI Studio يبني الموقع، لكنه لا يحول المتصفح إلى مدير Windows. يطلب من Build إنشاء Agent Contract وMock Agent Simulator فقط، ما لم يتم تزويده لاحقًا بكود Agent مستقل.

•	Agent هو تطبيق مستقل خارج المتصفح، يعمل بصلاحيات المستخدم، ولا يفتح منفذًا عامًا.
•	Pairing يعرض Code في الويب؛ Agent يرسله مع public key؛ الخادم يربطه بالمستخدم مرة واحدة.
•	Heartbeat يعلن version وOS وcapabilities وlastSeenAt فقط.
•	Job لا يُنفذ إذا capability غير موجودة أو التوقيع/nonce/expiry غير صالح.
•	Payload الحساس لا يمر بالسحابة في v1؛ واجهة الويب تطلب العملية وAgent يتعامل محليًا مع Windows/Device session.
•	النتيجة تتضمن evidence وverified، وتُمرر على Redaction قبل الإرسال.
•	Mock Agent Simulator يسمح باختبار الواجهة بحالات success/failure/null، وكل بياناته synthetic=true.
12. Gemini داخل الموقع
•	الميزة اختيارية: Explain this result، Create safe checklist، Summarize audit.
•	لا يُسمح للنموذج بإصدار ادعاء Telemetry غير موجود في البيانات.
•	لا Tool execution مباشر من Gemini في الإصدار الأول.
•	لا إرسال أسرار أو raw logs قبل Redaction.
•	كل جواب AI يعرض تنبيه: تفسير مساعد وليس قياسًا جديدًا.
•	الاستدعاء server-side فقط، مع rate limit وحدود حجم الإدخال.

17. النص الرئيسي الجاهز للصق في Build
Build a production-minded full-stack web application named “Vortex Network Control Center Web” using React + TypeScript for the client and Node.js + TypeScript server routes. The default UI language is Arabic RTL with an English toggle. Use a premium dark network-operations visual system, responsive down to 320px, keyboard accessible, with clear loading, empty, failed, unverified, stale, unavailable, and NOT_IMPLEMENTED states.

Critical truth rule: a browser or Cloud Run service cannot directly manage the user’s Windows Wi-Fi or private LAN. Build a cloud dashboard plus a Local Agent contract. Never pretend the browser can scan Wi-Fi, read router RF metrics, or access private IPs. Without an online paired agent, local operations must return AGENT_OFFLINE or NOT_IMPLEMENTED. Provide a Mock Agent Simulator for development and mark every simulated value synthetic=true.

Use Firebase Authentication with Google sign-in and Firestore with strict per-user ownership rules. Create collections for users, workspaces, agents, devices, telemetry, jobs, jobResults, auditEvents, and ispProfiles. Do not store Wi-Fi/router passwords, cookies, authorization headers, API keys, PLOAM, LOID, or device secrets in Firestore, browser storage, logs, or AI prompts.

Implement these pages: public Landing, Sign in, Onboarding, Dashboard, Agents, Devices, Wi-Fi, Diagnostics, Repairs, Monitoring, Audit, and Settings. Every telemetry card must show source, verified status, capturedAt, and stale status. Missing metrics are null and charts skip null values.

Implement server APIs for health, current user, agent pairing, agent heartbeat, agent revoke, devices, jobs, job claim/result, telemetry, diagnostics, repair preview/execute, audit, and AI explain. Validate inputs with shared schemas, enforce authentication and owner scope server-side, add CSRF protection for mutating browser requests, rate limits, security headers, redaction, replay protection, signed agent results, and no-store for sensitive responses.

The Local Agent contract uses one-time pairing codes, public keys, nonces, timestamps, signatures, expiring jobs, capabilities, heartbeat, and explicit consent. Jobs use these states: QUEUED, CLAIMED, RUNNING, VERIFIED_SUCCESS, FAILED, UNVERIFIED_RESULT, CANCELED, EXPIRED, NOT_IMPLEMENTED. Do not implement direct remote device changes in v1. Router, NanoStation, and ONT modifications remain hidden and NOT_IMPLEMENTED until a tested provider and real device validation exist. Ping proves reachability only and never proves RSSI, CCQ, AirMAX, O5, LOS, optical power, or temperature.

Add an optional server-side Gemini “Explain result” feature. It may summarize existing redacted evidence but must not generate new measurements or execute repairs. Keep GEMINI_API_KEY server-side only.

Create automated unit, API integration, security, agent-contract, UI, and end-to-end tests. Add a README with setup, Firebase configuration, secrets, local development, test commands, GitHub sync, Cloud Run deployment, limitations, privacy model, and rollback steps. Do not stop after generating a visual prototype. Continue until npm install, typecheck, lint, tests, and production build pass. Show actual test and build results, and do not claim anything was verified unless it was executed successfully.
