VORTEX NETWORK CONTROL CENTER v2.0
الخريطة الهندسية التنفيذية النهائية
Zero Fake Telemetry • Zero Fake Operations • Fail Closed

حالة الوثيقة
مرجع نهائي للتنفيذ والمراجعة والاختبار. لا تُعد أي وظيفة "منفذة" إلا بعد اجتياز اختبار القبول المرتبط بها. الميزات التي تحتاج جهازًا فعليًا تبقى Pending Device Validation.

المسار المعتمد: C:\VortexNetworkCenter
المنصات المستهدفة: Windows 10/11 • Windows PowerShell 5.1 • Python 3.10+
المراجع الداخلية: الملفات السبعة المرفقة بالمشروع، مع اعتماد الأحدث والأكثر تحديدًا عند التعارض.
 
1. الملخص التنفيذي
تهدف هذه الخريطة إلى إعادة بناء المشروع على أساس قابل للتحقق، مع الحفاظ على سهولة التثبيت عبر الحافظة، لكن بعد إضافة فحص AST والنسخ الاحتياطي الموثق والاختبارات الإلزامية. المرجع التنفيذي الأعلى هو المتطلبات الأمنية والتصحيحات الحديثة، أما الكود الحالي فهو نقطة انطلاق تحتاج إعادة هندسة وليس نسخة معتمدة.
المبدأ الحاكم
لا نجاح بلا دليل. لا قياس بلا مصدر. لا Rollback بلا تحقق. لا Provider بلا Fingerprint ومصادقة وParser مختبر. لا أسرار خارج DPAPI أو الذاكرة المؤقتة المراقبة.

•	عدم لمس VortexAI أو أي عملية Python لا يملكها المضيف الحالي.
•	فصل اتصال Wi-Fi المحفوظ عن الاتصال ببيانات اعتماد جديدة.
•	منع قيم ONT/NanoStation الوهمية؛ Ping يعني Reachability فقط.
•	إرجاع NOT_IMPLEMENTED للوظائف غير المنفذة وإخفاء أزرارها.
•	تشغيل PreBuild قبل بناء EXE، وPostBuild بعده، ومنع الإطلاق عند أي فشل.

6. المعمارية ودورة الحياة
1.	Installer يتحقق من النص، يأخذ Backup متحققًا، يكتب الملفات، يشغّل PreBuild، يبني EXE ثم يشغّل PostBuild.
2.	EXE يطلق Python كعملية ابن، يحتفظ بالـ PID، يراقب stderr، وينتظر server_port.txt ثم /api/health.
3.	Backend ينشئ Tokens في الذاكرة، يربط 127.0.0.1:0، ويكتب port file ذريًا.
4.	Frontend يحصل على الرموز عند تقديم index.html ويستخدم XHR محليًا فقط.
5.	Shutdown محمي بـ Session + CSRF + Host nonce، ويُنفذ من خيط منفصل.
6.	المضيف ينتظر إغلاقًا منظمًا حتى 5 ثوانٍ، ثم يستخدم Kill للعملية التابعة فقط كحل أخير ويسجل الإغلاق القسري.
قيد معماري
IE11 WebBrowser يُقبل للإصدار الحالي فقط. يسجل كدين تقني مرتفع، ويُقترح WebView2 في إصدار لاحق دون تغيير نطاق v2.0.

8. دورة Wi-Fi الموثوقة
8.1 الاتصال ببيانات اعتماد جديدة
7.	الحصول على Lock قبل إنشاء attemptId؛ إذا كان مشغولًا يعاد ATTEMPT_IN_PROGRESS.
8.	التقاط Baseline: SSID/BSSID/Profile/IP وآخر WLAN EventRecordID.
9.	فحص حديث وإثبات وجود SSID وجمع BSSIDs ونوع المصادقة والتشفير.
10.	إنشاء XML عبر ElementTree، وProfile يدوي معزول _vortex_verify_<attemptId>.
11.	بدء الاتصال ومراقبة Cancellation وWLAN events بعد baseline وعدم وجود AUTH_FAILED.
12.	التحقق من Active Profile ثم SSID وBSSID وIPv4 غير APIPA وGateway.
13.	إذا غاب حدث نجاح موثوق مع بقاء مؤشرات الاتصال، النتيجة UNVERIFIED_RESULT وليست نجاحًا.
14.	ترقية محسوبة إلى Profile دائم، ثم إعادة التحقق؛ لا يُحذف Profile الاختبار قبل ثبوت الدائم.
15.	في finally: تصفير XML كامل الحجم، flush، fsync، حذف الملف وProfile الاختبار، وتحرير Lock بواسطة المالك فقط.
8.2 الاتصال بملف محفوظ
•	مسار مستقل لا يستدعي Scan كشرط إلزامي، لدعم Hidden وEnterprise المحفوظة.
•	لا ينشئ PSK ولا يعدل Profile المحفوظ.
•	يتحقق من Active Profile وSSID وIP/Gateway، ويرجع UNVERIFIED_RESULT إذا تعذر إثبات المصادقة.
•	Profile name لا يُفترض أنه يساوي SSID.
9. Backup وRollback لـ Wi-Fi
يُعامل الاستبدال النهائي لـ Profile كعملية Transaction ذات نقاط فشل واضحة.
16.	لا Backup ولا Restore ما دام Profile الأصلي لم يتغير.
17.	قبل تعديل الأصل: تصدير مناسب، تسجيل الحجم والبصمة وحماية الملف، وتحديد previousProfileModified=true.
18.	بعد تثبيت الدائم: إثبات وجوده ونشاطه وتطابق SSID/BSSID وIPv4/Gateway.
19.	عند الفشل: محاولة Restore مرة واحدة فقط إذا تغير الأصل.
20.	إذا فشل أمر الاستعادة: RESTORE_FAILED. إذا نجح الأمر دون تحقق اتصال: RESTORE_NOT_VERIFIED.
21.	rollbackAvailable يصبح true فقط إذا كانت آلية الاستعادة متاحة واختبارها المرتبط ناجحًا، وليس لمجرد وجود ملف.
10. الأمن وإدارة الأسرار
النطاق	القاعدة	اختبار القبول
Vault	DPAPI فقط؛ لا fallback؛ fail closed	فشل DPAPI لا يكتب ملفًا بديلًا.
Atomic writes	temp + flush + fsync + replace	انقطاع الكتابة لا يفسد الأصل.
Sessions	SESSION_ONLY أو PERSIST_ENCRYPTED منفصلان عن الصلاحية	Summary بلا password.
Redaction	Password/Passphrase/Key/Auth/Cookie/API/Session/CSRF	عينات اختبار لا يظهر منها السر.
Reveal	Token مرة واحدة 30s وno-store	الاستهلاك الثاني يفشل.
Clipboard	المسح فقط إذا بقيت الحافظة تحتوي السر نفسه	لا يمسح محتوى جديدًا للمستخدم.
Temp XML	مسح كامل الحجم ثم حذف	لا يبقى XML أو Profile اختبار.
Audit	كتابة ذرية وفشل ظاهر	خطأ الحفظ ينتج حالة قابلة للرؤية.

11. Provider Registry والأجهزة الخارجية
الدعم الحقيقي يتطلب Fingerprint + Authentication proof + Parser + Device Test. ما دون ذلك Read-only أو NOT_IMPLEMENTED.
Provider	الإصدار الأول	شرط الترقية
Generic Router	Reachability وPorts وHeaders فقط	لا إدارة.
OpenWrt	Candidate integration	جهاز فعلي + ubus/rpcd موثق + Parser tests.
MikroTik	Candidate integration	RouterOS version مثبت + REST/API test.

ONT Huawei/ZTE/Nokia	Reachability وISP profile فقط افتراضيًا	Parser موثق لموديل محدد.

حظر ثابت
لا تعديل LOID أو PLOAM أو Serial أو OMCI أو GEM أو T-CONT أو TR-069 أو OLT-managed values. ولا استنتاج O5/LOS/Optical Power/Temperature من Ping.

تسرب Tokens	مرتفع	No-store + redaction + memory-only + compare_digest

20. القرارات المعتمدة للإصدار الأول
•	Python خارجي 3.10+ مطلوب؛ لا تنزيل تلقائي.
•	الحزمة AppBundle وليست Portable.
•	IE11 WebBrowser يبقى في v2.0 مع تسجيله دينًا تقنيًا.
•	عمليات تعديل أجهزة Router/Nano/ONT تبقى NOT_IMPLEMENTED حتى نجاح Device Tests.

•	كشف كلمة مرور Wi-Fi اختياري ويمكن تعطيله من settings، مع Token مرة واحدة.
•	حد الطلب 64 KB.
•	Graceful shutdown مهلة 5 ثوانٍ قبل القتل القسري للعملية التابعة فقط.
